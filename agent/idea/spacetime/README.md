# Idea Generator SpacetimeDB integration module

This is an actual SpacetimeDB TypeScript module, pinned to `spacetimedb 2.10.2`. It stores authorized Idea jobs, input hashes, authorization revisions, worker leases, and validated worker responses. All raw tables are private. `my_idea_jobs` is an authenticated view that returns only current jobs visible to the caller's room grant.

The module has passed TypeScript checks and tests that call its actual SDK-wrapped reducers against an in-memory database context. A native host shim permits those tests in Node. The integration branch additionally published to an isolated local 2.10.2 server and tested real subscriptions, competing claims, cached replay, retries and access isolation. This is not a cloud deployment. See [Workflow integration](../../../workflow/INTEGRATION.md).

## Ownership and trust

At initialization, the publishing owner's identity is stored. Only that owner can invoke `grant_room` and `revoke_room`. There are two server roles per room:

| Role | Capabilities |
| --- | --- |
| `workflow` | Advance room revisions, enqueue complete authorized requests, read current jobs/results |
| `worker` | Claim a known job, read its claimed snapshot, commit its result, read current completed results |

Use separate authenticated server identities. Do not give browser users workflow/worker grants or their tokens. Ordinary users receive their UI data through the main application's own permission checks. A query filter is not an access-control boundary; the view checks the caller's granted identity on the server. [SpacetimeDB access permissions](https://spacetimedb.com/docs/tables/access-permissions/)

This module is a job persistence integration, not the human event state machine. The trusted Workflow must first verify membership, source-sharing consent, real human convergence/reviews, all contract semantics, and finite execution budgets. The worker runs the full request/response validators before committing. The reducers independently protect identity, request envelope, hash, revisions, and lease ownership; they do not independently prove the provenance of a trusted Workflow's human events.

## Reducers and view

Database names use SpacetimeDB's default snake case. Generated TypeScript SDK methods use the corresponding camel case exports.

| Server function | Parameters | Behavior |
| --- | --- | --- |
| `grant_room` | `roomId, identity, role` | Owner sets a server identity's role in one room |
| `revoke_room` | `roomId, identity` | Owner immediately removes that identity's access |
| `advance_room_revision` | `roomId, inputRevision, authorizationRevision` | Workflow updates monotonic u64 counters; stale jobs disappear from the view |
| `enqueue_idea` | `requestJson, authorizationRevision` | Workflow stores canonical request JSON and server-computed SHA-256; conflicting ID reuse fails |
| `claim_idea` | `roomId, requestId, attemptId` | Worker obtains a five-minute execution lease; competing attempts fail with `IN_PROGRESS` |
| `commit_idea` | `roomId, requestId, attemptId, requestHash, authorizationRevision, responseJson` | Worker atomically checks current revisions and lease, then saves the response |
| `my_idea_jobs` | authenticated caller | Current snapshots/results visible to that identity |
| `publish_board` | roomId, revision, ideaRevision, snapshotJson | Workflow-only, monotonic shared projection |
| `my_workflow_boards` | authenticated workflow caller | Authorized room projections, no private interviews |
| `retry_idea` | roomId, requestId | Workflow clears an error outcome for an explicit retry |

`attemptId` is a random UUID or another unique 16–128 character `[a-zA-Z0-9_-]` token generated by the worker orchestration. A retry of the same claim acknowledgement must reuse it. Separate executions must use separate attempt IDs, even if they share a worker identity. Do not expose lease tokens to the model.

Bound model execution plus commit time below the five-minute lease. The module does not automatically renew leases or retry model calls. If a lease expires, a new worker may claim it; a result from the old attempt is rejected. A response cache is returned only while the request's input and authorization revisions remain current. Cached error responses are audit results and do not advance the product workflow.

The room revision is deliberately conservative: any relevant revision change invalidates old room jobs. The main Workflow should call `advance_room_revision` before enqueuing the new authorized request, and immediately when consent is withdrawn. This does not erase already disclosed information or delete remote Mem0 entries; the main application schedules those cleanup operations separately.

## Bind the JavaScript runtime

`../memory.mjs` exports `createSpacetimeContextStore({loadSnapshot,commitResult})`. Bind the callbacks using the client bindings generated from this module. Each runtime request uses a separate attempt context:

1. `loadSnapshot` calls generated `connection.reducers.claimIdea({roomId,requestId,attemptId})` and waits for its committed result. A competing claim error stops before a model call.
2. Subscribe to `SELECT * FROM my_idea_jobs` with the worker identity. Wait for the matching claim/result row to be applied; never reuse a cached row from before the claim transaction. Check `row.operation` and, for a running row, `row.attemptId`.
3. Return `{request:JSON.parse(row.requestJson),authorization_revision:Number(row.authorizationRevision)}`. For a completed row also return `response:JSON.parse(row.responseJson)`. Retain `requestHash` and attempt ID in the trusted request context.
4. `commitResult` calls generated `connection.reducers.commitIdea` with the same request ID, attempt, stored hash, supplied authorization revision and serialized validated response. Convert safe-integer revisions to `BigInt` for the SDK.
5. Wait for the committed response row to apply, then return `JSON.parse(row.responseJson)`. Propagate permission, conflict, stale revision, and lease errors; do not return an unsaved result as if committed.

The generated bindings and real SDK callbacks now live in `workflow/node/`. The server adapter provisions separate identities and forwards authorized change notifications through the workflow HTTP server. Configuration is private and deployment-specific. See the [TypeScript quickstart](https://spacetimedb.com/docs/quickstarts/typescript/) for generated client bindings.

## Local verification and deployment boundary

Requires Node 22.19 or later for the Node test harness.

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm typecheck
pnpm test
```

The optional `pnpm build` invokes an already-installed SpacetimeDB CLI. The CLI is not installed by this package. Follow the [official TypeScript quickstart](https://spacetimedb.com/docs/quickstarts/typescript/) to build/publish into the intended development database and generate bindings. Publishing is a separate deployment action; no database name, host, credential, or public table has been guessed.

Live acceptance checks should verify: two worker sessions racing for a claim yield one execution; revoking a grant removes view rows; consent revision changes invalidate the old snapshot; reconnecting returns the same cached result; expired attempts cannot overwrite a new result. Keep test rooms and fixtures separate from real member data.
